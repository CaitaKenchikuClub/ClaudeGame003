# 広告（AdMob・ハウス広告）の仕組みと設定

最終更新：2026-10-15（フェーズ1：Web版・模擬広告まで実装。アプリ版の実機確認はフェーズ2で行う）

## 1. 何が出るか

| 画面 | バナー広告 | リワード広告（コンティニュー） |
|---|---|---|
| タイトル画面 | ○（アプリ版のみ。カードが収まる画面の大きさのときだけ） | — |
| **プレイ中・ポーズ中** | **×（出さない）** | — |
| ライフ0の確認カード | ×（出さない） | 「広告を見てライフ＋1」で表示 |
| 結果画面（ごちそうさま!） | ○（アプリ版のみ。条件は同上） | — |
| 設定メニューを開いている間 | ×（スライダーなどの近くに出さない） | — |

- **プレイ中にバナーを出さない理由**：このゲームは画面のどこでもドラッグして操作できるため、バナーと操作領域が隣り合い、誤タップの危険があるため（AdMob の実装ガイドラインの「操作部分の近くに広告を置かない」に従う）。
- **バナーの位置**：HUD（🔊・≡ ボタン）の下に 12px 以上空けて、ゲーム領域の一番上。タイトル・結果のカードは、バナーの下に 12px 以上空けて中央に表示する。カードが入りきらない小さい画面（例：幅320×高さ568）では、バナーを出さない。
- **インタースティシャル広告は使わない**（オーナー方針）。

## 2. コンティニュー（リワード広告）の流れ

1. ライフが0になった瞬間にゲームを凍結する（落下・時間・難易度・鳥がすべて止まる）。ベストスコアはこの時点で保存する。
2. このプレイでまだコンティニューしていなくて、広告を出せるときだけ確認カードを表示する（出せないときは今までどおり結果画面へ）。
   - ［広告を見てライフ＋1］ ／ ［コンティニューせずに終了する］
3. 広告を見ている間は、ゲームを凍結したまま、ゲームの音も止める。
4. **報酬を獲得したときだけ**ライフを1にして、「3・2・1」のカウントダウンのあと再開する。再開後2秒間は無敵（ライフが減らない。キャラが点滅する）。スコア・経過時間・難易度・落ちているアイテムはそのまま。
5. 途中で閉じた場合は回復しない。確認カードに戻り、「広告を最後まで見ると、ライフ＋1になります。」と［もう一度広告を見る］［コンティニューせずに終了する］を表示する（2026-10-15 追加）。
   - 再視聴は毎回プレイヤーがボタンで選ぶ（自動では流さない）。回数の上限はない。
   - 次の AdMob 広告がまだ読み込めていなければ、待たせずにハウス広告を出す。
   - SDK からは「報酬なしで閉じた」としか分からないため、不具合で閉じざるを得なかった場合も、自分で閉じた場合も同じ扱い。
   - AdMob の広告が**読み込めていない**とき、または**表示に失敗した**とき（通信エラーなど）は、代わりにハウス広告を表示する。ハウス広告を閉じればコンティニューできる（2026-10-15 変更）。
6. ライフの回復（コンティニュー）は**1プレイにつき1回まで**。

**報酬の二重付与や取りこぼしの防止（`ads.js` の `showAdmobRewarded`）**
- 「報酬」（Rewarded）と「閉じた」（Dismissed）の通知は、どちらが先に届いても正しく判定する。閉じた後に報酬が遅れて届くことがあるため、閉じてから最大1秒待ってから「報酬なし」と判定する。
- 判定は1回だけ（`settle`）。その後に同じ通知が何回届いても無視する。
- ゲーム側でも「このプレイでコンティニュー済み」（`contUsed`）で二重付与を防ぐ。

## 3. 広告の出し先（`ads.js` が自動で切り替える）

| 動いている場所 | バナー | リワード（コンティニュー） |
|---|---|---|
| アプリ版（Capacitor）で AdMob が使える | AdMob アンカー アダプティブ バナー | AdMob リワード広告。読み込めていない・表示に失敗したときはハウス広告 |
| アプリ版で AdMob が使えない（同意が得られない・SDK エラー・本番 ID が未設定） | なし | ハウス広告 |
| **Web版（GitHub Pages）** | なし | **ハウス広告** |
| Web版で URL に `?ads=mock` を付けたとき（開発用） | 模擬バナー | 模擬リワード（AdMob と同じ流れで、成功・キャンセル・失敗を選べる） |

**ハウス広告**：けんちくぶの告知画像（`ads-config.js` の `houseAd`）を全画面に表示（比率を保って画面内に収める）。画像をタップするとリンク先を開く。5秒たつと右上に × が出て、閉じるとコンティニューできる。
- × のタップ判定は 72×72px で、画像とは重ならない位置（上のバー）にある。
- アプリを切り替えている間は、5秒の待ち時間が進まない。

## 4. 設定の変え方（`ads-config.js` だけを編集する）

- **ハウス広告の画像・リンク先**：`houseAd.image`（画像ファイルのパス）と `houseAd.url` を書き換える。画像は `assets/ads/` に置く。縦長・横長どちらでもよい。表示秒数は `closeAfterSec`。
- **本番の広告ユニット ID**：AdMob の管理画面で作成したら `admob.production` に入れ、ストア公開用のビルドでだけ `useTestAds: false` にする。
  - **テスト用 ID のままストアに出さないこと／開発中に本番 ID で自分の広告をタップしないこと**（アカウント停止の原因になる）。
  - `useTestAds: false` で本番 ID が空のときは、AdMob を使わずハウス広告だけになる（安全側）。
- テスト用 ID（Google 公式）：Android バナー `ca-app-pub-3940256099942544/9214589741`、Android リワード `ca-app-pub-3940256099942544/5224354917`、iOS バナー `ca-app-pub-3940256099942544/2435281174`、iOS リワード `ca-app-pub-3940256099942544/1712485313`（iOS の2つはフェーズ2で Google の公式ページと照合すること）。

## 5. 開発用の模擬広告（`?ads=mock`）

`https://caitakenchikuclub.github.io/ClaudeGame003/?ads=mock` のように URL の最後に付けると、AdMob の代わりの模擬広告で動きを確かめられる。

| 追加のパラメータ | 再現する状況 |
|---|---|
| `&fail=reward` | リワード広告が読み込めない（→ハウス広告が出る） |
| `&fail=banner` | バナーが読み込めない（→何も出ず、余白も取らない） |
| `&order=late` | 「閉じた」の通知が「報酬」より先に届く |
| `&dup=1` | すべての通知が2回ずつ届く |
| `&privacy=1` | 同意管理（UMP）で「プライバシー設定」の入口が必要な地域 |
| `&loaddelay=2000` | リワード広告の読み込みに 2000 ミリ秒かかる（途中で閉じた直後の再視聴でハウス広告になる動きの確認用） |

## 6. フェーズ2（Capacitor 導入時）にやること

1. `npm i @capacitor-community/admob@8`（2026-10-15 時点で 8.2.1。Capacitor 8.5 以上、iOS 15 以上、Android API 24 以上）→ `npx cap sync`
2. アプリ ID を設定する（開発中は Google のテスト用アプリ ID）。
   - Android：`AndroidManifest.xml` の `<application>` に `com.google.android.gms.ads.APPLICATION_ID`（テスト用 `ca-app-pub-3940256099942544~3347511713`）
   - iOS：`Info.plist` に `GADApplicationIdentifier`（テスト用 `ca-app-pub-3940256099942544~1458002511`）と `SKAdNetworkItems`
   - iOS の「トラッキングの許可（ATT）」は**使わない**方針なので、`NSUserTrackingUsageDescription` は入れず、`requestTrackingAuthorization` も呼ばない（`ads.js` は呼んでいない）。
3. AdMob の管理画面「プライバシーとメッセージ」で、EEA・英国向けの同意メッセージ（GDPR）を作成する。`ads.js` は起動時に同意情報を確認し、必要なら同意画面を出す。プライバシー設定の入口は、必要な地域だけ設定メニューに表示される。
4. ハウス広告のリンクをアプリの外のブラウザで開くため、`@capacitor/browser` を入れる（入っていれば `ads.js` が自動で使う）。
5. 実機で確認する（**まだ確認していない**）：
   - バナーの位置。特に **iOS**：プラグイン 8.2.1 は上配置の margin を逆向きに扱う作りのため、`ads.js` では iOS だけ負の値を渡している。HUD の下に正しく出るか、セーフエリア（ノッチ）との関係を確認する。プラグインを更新したら再確認。
   - Android の全画面表示（edge-to-edge）でのバナー位置
   - リワード広告：最後まで見る・途中で閉じる・機内モード（読み込み失敗）・広告の途中でホームに戻って再開
   - 同意画面（EEA 向けのテストは UMP のデバッグ地域設定を使う）
6. ストア公開に向けて：プライバシーポリシーのページ、`app-ads.txt`（開発者のウェブサイトのトップに置く必要がある）、Google Play の「データ セーフティ」、App Store の「App のプライバシー」の申告。
