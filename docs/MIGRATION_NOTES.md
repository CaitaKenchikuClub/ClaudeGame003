# 移行メモ：Claude アーティファクト → GitHub Pages

## A. 分析

### A-1. 元ファイルの構造
- 1ファイルのみ（約425KB）。そのうち約390KBは **base64 で埋め込まれた WebP 画像4枚**で、プログラム本体は約34KB。
- 構成：基本 CSS → ゲーム CSS → HTML（HUD／canvas／オーバーレイ）→ `<script>`（`SND` サウンドエンジン＋ゲーム本体の即時関数）。
- ゲーム描画はすべて **Canvas 2D**（キャラは画像、アイテム・鳥・背景はコードで描画）。
- 音はすべて **Web Audio API で合成**（音声ファイルなし）。

### A-2. 外部ライブラリ
| 種類 | 内容 | 備考 |
|---|---|---|
| JavaScript ライブラリ | **なし**（素の JavaScript のみ） | ビルド不要 |
| フォント | Google Fonts（Dela Gothic One、M PLUS Rounded 1c） | インターネット接続が必要。オフライン時は代わりのフォント（ヒラギノなど）で表示される |

### A-3. Claude アーティファクト環境への依存
| 箇所 | 内容 | GitHub Pages での影響 |
|---|---|---|
| 1行目 | アーティファクト環境が自動で付けた外枠（`<!doctype>`、`<head>`、セーフエリア余白などの基本 CSS） | そのままでも動く。ただし `<title>` などが `<body>` の中にあり、HTML としては正しくない |
| `<meta name="claude:viewport-fit-sides">` | Claude 専用の指示 | 他の環境では意味がない（無害） |
| 画像の base64 埋め込み | アーティファクトは1ファイルにする必要があったため | 動くが、ファイルが重く編集もしにくい |
| `window.claude` などの専用 API | **使っていない** | 影響なし |
| `localStorage` | 普通のブラウザ機能 | 動く。ただし保存先がサイトごとに別なので、アーティファクト版の記録は引き継がれない |

### A-4. GitHub Pages への移行で問題になりそうな点
1. `<head>` の構造が正しくない（上記）→ **修正した**
2. 画像の base64 埋め込み → **別ファイルに分けた**
3. `localStorage` の共有：`caitakenchikuclub.github.io` の下にある**すべてのリポジトリの Pages で同じ保存領域**を使う。キー名に `broc-` という接頭辞が付いているので、別のゲームとぶつかる心配は小さい → **変更なし**（キー名を変えると記録が消えるため）
4. パス：URL が `/ClaudeGame003/` というサブパスになる → 画像は相対パスにしたので問題なし
5. 自動再生の制限：最初のタップで音を出す処理が元からある → 問題なし
6. HTTPS：GitHub Pages は HTTPS なので、振動や Web Audio も使える

## B. 実装（今回の変更）

**ゲームの CSS と JavaScript は1文字も変えていません**（元ファイルと比べて一致することを確認済み）。

| 変更 | 内容 |
|---|---|
| `<head>` の整理 | `<html lang="ja">`、`<meta charset="utf-8">`、viewport、`<title>`、フォントの読み込みを `<head>` に移動。アーティファクト環境が入れていた基本 CSS も、見た目を変えないため `<head>` にそのまま残した |
| Claude 専用 meta の削除 | `claude:viewport-fit-sides` を削除 |
| 画像の分離 | base64 画像4枚を `assets/img/*.webp` に書き出し、`<img src>` を相対パスに変更（画像データ自体は同じもの） |
| `.nojekyll` | GitHub Pages の Jekyll 処理を止める（静的ファイルをそのまま配信させる） |
| 元ファイルの保存 | `archive/original-artifact.html` に元ファイルをそのまま保存 |
| テスト | `tests/smoke-test.mjs` を追加 |

## D. Capacitor でアプリ化する際の注意点（今後の参考）

1. **フォルダ構成**：Capacitor はアプリに入れるファイルを1つのフォルダ（`webDir`、例：`www/`）にまとめる必要がある。アプリ化の段階で、ゲームのファイルを `www/` に移し、GitHub Pages も GitHub Actions で `www/` を公開する形に変えるのが分かりやすい（今回は初めての公開を簡単にするため、ルートに置いている）。
2. **Google Fonts**：アプリはオフラインでも動くべきなので、フォントファイルを同梱する（どちらのフォントも SIL Open Font License で、同梱できる）。
3. **保存データ**：iOS の WebView は、端末の空き容量が少ないと `localStorage` を消すことがある【一般的な注意点】。大事なデータが増えたら `@capacitor/preferences` に移すことを検討する（`broc-best` の移し替え処理が必要）。
4. **振動**：iOS は `navigator.vibrate` に対応していない。アプリでは `@capacitor/haptics` を使うと振動させられる。
5. **音**：iOS はマナーモードのとき Web Audio が鳴らないことがある【推測：要実機確認】。最初のタップで音を出す処理は元からある。
6. **アプリの切り替え**：`visibilitychange` で音は止まる。ゲームの一時停止はないので、アプリでは一時停止機能があると良い（新機能として検討）。
7. **Android の戻るボタン**：今は何も処理していない（`@capacitor/app` で対応可能）。
8. **画面の向き**：縦画面に固定する設定をネイティブ側で行う。
9. **セーフエリア**：`viewport-fit=cover` と `env(safe-area-inset-*)` は対応済み。Android の全画面表示（edge-to-edge）では実機で確認が必要。
10. **古い WebView**：`color-mix()` と `roundRect()` を使っているため、Android System WebView 111 未満、iOS 16.2 未満では表示が崩れたりエラーになったりする可能性がある。アプリの対応 OS バージョンを決めるときに考慮する。
11. **広告**：Web（AdSense など）とアプリ（AdMob）では仕組みが違う。`ads.js` に「広告を表示する」という共通の関数を用意し、その中で Web かアプリかを判定して切り替える設計にすると、ゲーム本体を共通化できる。
12. **ストア公開**：プライバシーポリシーのページ（広告を入れる場合は必須）、アプリアイコン、スクリーンショット、iOS は Mac と Apple Developer Program（年額）、Android は Google Play Console（初回登録料）が必要。
