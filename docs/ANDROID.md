# Android アプリ版（Capacitor）

最終更新：2026-10-16（オーナーがスマホでの起動を確認済み。けんちくぶ！のロゴ画面と白い起動画面を追加。ロゴ画面・起動画面の実機確認はまだ）

## 1. しくみ
- Web 版（GitHub Pages）と Android アプリは**同じファイル**（`index.html`・`ads*.js`・`share*.js`・`assets/` など）を使う。
- `npm run sync` を実行すると、ゲームに必要なファイルだけを `www/` に集め（`scripts/build-web.mjs`）、Android プロジェクト（`android/`）の中にコピーする。アプリにはファイルが**同梱**されるので、ネットがなくても起動する。
- `docs`・`tests`・`archive`（Google Fonts を読む古いファイル）・`design` はアプリに入れない。
- GitHub Pages は今までどおりリポジトリのルートを公開する。`package.json`・`android/` などを足しても Web 版には影響しない。
- `www/`・`node_modules/`・`resources/` は自動で作られるフォルダなので、git の管理対象外。
- PWA について：オフライン用のキャッシュ（Service Worker）は使っていないので、アプリ版に古いファイルが残る問題は起きない。`manifest.webmanifest` はアプリ内では使われない。

| 項目 | 値 |
|---|---|
| アプリ名 | ブロッ校長！ |
| Application ID | `com.caitakenchikuclub.burokocho`（**Google Play で公開した後は変えられない**） |
| バージョン | versionCode 1 ／ versionName 1.0（`android/app/build.gradle`） |
| 対応 OS | Android 7.0（API 24）以上。targetSdk 36 |
| 画面の向き | 縦画面に固定（`AndroidManifest.xml` の `screenOrientation="portrait"`）。※Android 16 以降のタブレットなど大きな画面では、OS の決まりで横にもなる |
| Capacitor | 8.5.3（core・cli・android）。プラグイン：App 8.1.2、Toast 8.0.1、Share 8.0.3、Filesystem 8.1.5 |

## 2. オーナーが Mac でやること

### 2-1. はじめての準備（1回だけ）
1. Mac の「ターミナル」で、リポジトリのフォルダに移動する（例：`cd ~/ClaudeGame003`。フォルダの場所はクローンした場所）。
2. 作業ブランチを取ってくる：
   ```
   git fetch origin
   git checkout claude/ecstatic-hypatia-xvwuy1
   git pull
   ```
   （main にマージした後なら `git checkout main` → `git pull`）
3. `node -v` で **v22 以上**か確認する。古い場合は https://nodejs.org/ から LTS 版（22 以上）を入れ直す。
4. 必要な部品を入れる（package-lock.json に書かれた版がそのまま入る）：
   ```
   npm ci
   ```

### 2-2. Android Studio で開いてスマホで動かす
1. ゲームのファイルを Android プロジェクトに反映する：
   ```
   npm run sync
   ```
2. Android Studio で開く：
   ```
   npm run open
   ```
   （開かないときは、Android Studio の「Open」で、リポジトリの中の `android` フォルダを選ぶ）
3. 初回は右下に「Gradle sync」の進み具合が出て、数分かかる。「SDK がない」「Install missing platform」などと出たら、表示されたリンクを押してインストールする（Android SDK Platform 36 など）。
4. スマホの準備（Android）：
   1. 「設定」→「デバイス情報」（機種により「端末情報」）→「ビルド番号」を**7回**タップ →「開発者向けオプション」が有効になる
   2. 「設定」→「システム」→「開発者向けオプション」→「**USB デバッグ**」をオンにする
   3. USB ケーブルで Mac とつなぎ、スマホに出る「USB デバッグを許可しますか？」で「許可」
5. Android Studio の上のツールバーで、つないだスマホの名前を選び、緑の **▶（Run 'app'）** を押す。スマホにアプリが入り、起動する。
   - 2回目以降も、ゲームを直したら `npm run sync` → ▶ の順。
6. うまくいかないときは、下の画面に出る赤いエラーの文章をそのまま Claude に貼って相談する。

### 2-3. APK ファイルを作る場合（ケーブルなしで配りたいとき）
- Android Studio のメニュー「Build」→「Generate App Bundles or APKs」→「Generate APKs」。できた `app-debug.apk` をスマホに送ってインストールする（「提供元不明のアプリ」の許可が必要）。
- **Google Play に出すときは、署名した AAB（App Bundle）が必要**。これはストア公開の段階で手順を用意する。

### 2-4. Mac の Claude Code に頼む場合
Mac の Claude Code には「`docs/ANDROID.md` の 2-1 と 2-2 の手順で、Android アプリをビルドしてスマホで動かして」と頼めばよい。コマンドのエラーも Mac 側で直接調べられる。

## 3. アプリだけの動き

### 3-1. 戻るボタン（`index.html` の `onBack`。アプリ版だけで動き、Web 版では何もしない）
| 今の画面 | 戻るボタンを押すと |
|---|---|
| プレイ中 | ポーズメニューを開く |
| ポーズ・設定メニュー | とじる（プレイ中ならゲームに戻る）。「リトライしますか？」「ゲームをやめますか？」の確認・ライセンス情報を開いているときは、メニューに戻る |
| シェア画面 | とじる |
| コンティニューの画面・広告の表示中・3-2-1 のカウントダウン | 何もしない（誤操作を防ぐため） |
| タイトル画面・結果画面 | 1回目：「もう一度押すとアプリを終了します」とトースト（画面下の小さな通知）を出す。**2秒以内**にもう一度押すとアプリを終了する |

### 3-1-2. ポーズメニューの「ゲームをやめる」（アプリ版だけ）
- プレイ中のポーズメニューに「ゲームをやめる」ボタンを出す（タイトル・結果画面の設定メニューには出さない）。Web 版はブラウザのタブを閉じられないので、ボタンを出さない。
- 押すと確認ダイアログ（「ゲームをやめますか？」「今回のスコアは記録されず、アプリを終了します。」）を出す。「やめる」で `App.exitApp()` を呼んでアプリを終了する。「このまま続ける」か戻るボタンでメニューに戻る。
- プレイ中はベストスコアを保存していないので、やめた回のスコアは記録されない。

### 3-2. アイコン・スプラッシュ（起動画面）
- アイコンは `design/icon-source.webp`（校長のイラスト）から作る。丸や角丸に切り抜かれる機種では、絵の四隅が少し欠ける。
- スプラッシュ（OS が出す起動画面）：**白い背景の中央に角丸のアプリアイコン**。
  - Android 12 以降：`styles.xml` の `windowSplashScreenBackground`（白）と `windowSplashScreenAnimatedIcon`（`drawable-xxxhdpi/splash_icon.png`。OS が直径 160dp の円で切り抜くので、角丸の四隅がその円に収まる大きさにしてある）
  - Android 11 以前：`splash.png`（白い背景＋角丸アイコン）
- 作り直すとき：`npm run icons`（`scripts/make-app-icons.mjs`）。`android/app/src/main/res/` の画像が作り直される。

### 3-2-2. けんちくぶ！のロゴ画面（`index.html` の `#intro`。アプリ版だけ）
- 起動画面のあと、タイトル画面の前に、けんちくぶ！のロゴ（`assets/img/kenchikubu-logo.webp`）を出す。背景は薄い黄緑（`#eef8d0`）。
- 白い背景から、背景色とロゴがフェードで現れ（約0.8秒）、約2.6秒後にフェードで消えてタイトル画面になる。
- **音は出さない**。スマホをミュートにし忘れた人が、ここでミュートにできるようにするため。
- タップまたは戻るボタンでスキップできる。スキップのタップでは、ゲームも音も始まらない。今までどおり、タイトル画面での最初のタップで音が鳴り始める。
- Web 版では出さない（ロゴの画像もダウンロードしない）。

### 3-2-3. メディア音量が0のときは音を止めたままにする（2026-10-16）
- 不具合：メディア音量を0にしていても、広告を見終わったときやバックグラウンドから戻ったときに、電子音が一瞬鳴ることがあった（オーナーの実機で確認）。
- 対策：自作のネイティブプラグイン `MediaVolumePlugin.java`（`android/app/src/main/java/com/caitakenchikuclub/burokocho/`）がメディア音量とその変化をゲームに伝える。0のあいだは、ゲームの音の仕組み（Web Audio）を止めたままにし、効果音も予約しない。0より大きくなったら、短いフェードインで再開する（`index.html` の `SND.resume`）。
- 2026-10-17 追加の不具合：音量を0から上げた瞬間に、ノイズのような大きい音が一瞬鳴った（オーナーの実機で確認）。音の仕組みをいきなり止めると、スマホの音声バッファに止める直前の音が残り、再開したときにフェードインを通らずに上げた音量で鳴るため。
  - 対策（`SND.sleep`）：止めるときは、まず音を素早く0まで下げ、0.15秒後に止める（バッファに残るのは無音）。再開するときは0.1秒の無音を挟んでからフェードインする。音量0・バックグラウンド・広告の表示中のすべてで同じ止め方をする。
  - 自動テスト（`tests/android-test.mjs`）で、止める瞬間の出力が無音であることを確認している（直す前は鳴っている最中と同じ大きさだった）。
- 広告そのものの音は AdMob が出すもので、この対策の対象外。
- Web 版は今までと同じ。

### 3-3. 画面の端（セーフエリア）とステータスバー
- ゲームの画面は、今までどおり CSS の `env(safe-area-inset-*)` で、カメラの穴やナビゲーションバーと重ならないようにしている。Capacitor 8 の SystemBars がこの値を正しく渡す（古い WebView では、アプリ側でゲームの画面を内側に寄せる）。
- ステータスバーの文字・アイコンは黒（ゲームの背景が明るいため。`capacitor.config.json` の `SystemBars.style: "LIGHT"`）。画面の端の色はゲームの空の色。

## 6. 本番版（release）の署名とビルド（2026-10-17）
Google Play に出すファイル（AAB）は、**アップロード鍵**で署名する。Google Play では「Play アプリ署名」を使う（本当の署名鍵は Google が預かり、こちらはアップロード鍵で署名して出す）。

### 6-1. 鍵とパスワードの置き場所（オーナーの Mac）
| もの | 場所 | git |
|---|---|---|
| アップロード鍵 | `~/Keystores/burokocho-upload.jks`（別名 `upload`。RSA 2048、有効期限 2054年） | 入れない（`android/.gitignore` で `*.jks`・`*.keystore` を除外） |
| パスワード | macOS のキーチェーン（サービス名 `burokocho-upload-key`。「キーチェーンアクセス」アプリで確認できる） | 入れない |
| 鍵の場所の設定 | `android/keystore.properties`（鍵のパス・別名・キーチェーンのサービス名だけ。パスワードは書かない） | 入れない |

- `android/app/build.gradle` は、release のビルドを頼まれたときだけ、キーチェーンからパスワードを読む（開発版のビルドでは読まない）。
- 鍵の証明書の SHA-256：`74:1A:F7:F0:31:2B:34:B5:9B:EC:10:DB:BD:3B:BE:D4:F8:E1:1A:A4:2A:01:A0:57:E2:0D:82:66:B1:26:D2:84`
- **鍵ファイルとパスワードは、Mac 以外の安全な場所にもバックアップする**。なくした場合は、Play Console からアップロード鍵のリセットを申請できるが、日数がかかる。
- 別の Mac でビルドするとき：鍵ファイルを同じ場所にコピーし、`security add-generic-password -a "$USER" -s burokocho-upload-key -w` でパスワードを保存し、`android/keystore.properties` を作る（中身は下）。
```
storeFile=~/Keystores/burokocho-upload.jks
keyAlias=upload
keychainService=burokocho-upload-key
```

### 6-2. 本番版を作る
```
npm run sync
cd android
JAVA_HOME=~/Library/Java/JavaVirtualMachines/jbr-21.0.11/Contents/Home ./gradlew bundleRelease
```
- できるファイル：`android/app/build/outputs/bundle/release/app-release.aab`（これを Play Console にアップロードする）
- 実機で試す APK が欲しいときは `assembleRelease`（`android/app/build/outputs/apk/release/app-release.apk`）。開発版と署名が違うので、スマホに入れるときは開発版を先に削除する必要がある（ベストスコアなどのデータも消える）。
- **本番版は本番の広告 ID を使う**。自分のスマホで試す前に、AdMob でそのスマホをテストデバイスに登録すること（`docs/ADS.md` 4章）。
- 新しい版を出すたびに、`android/app/build.gradle` の `versionCode` を1つ増やす（`versionName` は表示用の版名）。最初の版は `versionCode 1`・`versionName "1.0"`。

### 6-3. 確認できたこと（2026-10-17）
- `bundleRelease`・`assembleRelease` で署名つきの AAB・APK ができ、署名の証明書が上の鍵のものと一致すること（`jarsigner`・`apksigner`）
- 本番版に、本番の AdMob アプリ ID が入っていること。debuggable（デバッグ用）になっていないこと
- 本番版の実機確認（ASUS Zenfone 10・Android 15。AdMob のテストデバイスに登録済みの端末）：
  - 開発版を削除して本番版（署名つき APK）を入れると、起動・タイトル画面まで正常。debuggable ではない
  - タイトル画面のバナーが**本番の広告ユニット ID**で読み込まれ、本物の広告に「テスト広告」のラベルが付いて表示された（テストデバイスの登録が効いている）
  - ライフ0 →「広告を見てライフ＋1」で、**本番の ID のリワード広告**が表示された（途中で Google Play の紹介画面が出る形式の広告）。最後まで見て × で閉じると、ライフ＋1 で再開した。2回目のライフ0では、コンティニューは出ずに結果画面になった（1プレイ1回）
  - AdMob の審査前・Google Play 登録前でも、本番の広告ユニットに広告が配信されることがある
  - 注意：テスト中に、広告の中のボタンが `adb shell input tap` に反応しないことがあった。その場合は手で操作する。テストデバイスに登録していない端末では、本番版の広告を押さない
- 本番版を入れたスマホで開発を続けるときは、本番版を削除してから開発版を入れ直す（署名が違うため。データも消える）
